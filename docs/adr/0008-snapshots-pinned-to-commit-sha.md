# Analyse repository snapshots pinned to a commit SHA

Ingest resolves the target branch to a commit SHA and downloads that tarball, instead of cloning. All derived data (Chunks and their embeddings) is stored under `owner/repo@sha`. Each Snapshot is embedded once per index version (ADR-0010): the chunker version plus the embedding model. When either changes, the Snapshot is deleted and ingested again. Re-asking about it costs no embedding calls, citations stay valid forever, and eval datasets can pin exact SHAs. Scope is capped at Python and TypeScript sources, at most 2,000 files, excluding vendored and generated code.
